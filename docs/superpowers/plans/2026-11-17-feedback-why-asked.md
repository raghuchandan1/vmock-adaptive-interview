# Feedback: why you were asked Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dashboard feedback shows what each question was checking, the follow-ups a panel may also ask, labelled follow-up reasons, and a follow-ups line on the Summary.

**Architecture:** One new model-written field per topic (`checking`) in the existing feedback call; one derived field (`expect_next`) built in `checkAndShapeFeedback` from `notAskedRungs` and `attributionUnasked`; rendering in `public/dash/feedback-v2.js` only.

**Tech Stack:** Node >= 18, no dependencies; vanilla JS page.

**Spec:** `docs/superpowers/specs/2026-11-17-feedback-why-asked-design.md`

## Global Constraints

- No agenda words (plan, criteria, rubric, probe/probing) or scores in new text; `checking` goes through `clean()`.
- `expect_next` never faults the student; `hr_round` is left out.
- Other feedback pages (/vmock v1-v3, `/student`) unchanged; new fields optional.
- `FEEDBACK_VERSION` 24 -> 25.

## Review Focus

- Topic too short to judge: `checking` and `expect_next` still shown (they help prepare). Covered by Task 1 (base fields).
- Model leaves `checking` empty: page shows no empty heading. Task 2 renders only when non-empty.
- Old cached feedback (version 24) opened: regenerated by version bump; renderer tolerates missing fields.
- No follow-ups in the interview: Summary card hidden. Task 2.
- A follow-up the interview ended on (unanswered): not counted in the Summary line. Task 2.
